\title{Written Skills Alter Validation Behavior Without Consistently Improving Repository Repair}
\author{Wang Qichen}
\date{}

\begin{document}
\maketitle

\begin{abstract}
Natural-language skills prescribe how a tool-using coding agent should inspect, edit, and validate a repository. Whether such procedures improve task success across models remains uncertain because behavioral changes and verified outcomes are often conflated. We introduce \SkillTraj{}, a frozen task pool and execution harness with external verifiers and complete tool-trajectory records. We evaluated 18 held-out repository-repair tasks across six model configurations in 870 scheduled runs, comparing a no-skill prompt (C0) with a fixed baseline skill (C1); a rewritten skill (v1) was explored on one weak target model. C1--C0 verifier-pass differences were small and inconsistent across models. For \QwenWeak{}, C1 changed task-paired post-edit validation by \(-25.0\)\pp{} while verifier pass changed by \(+1.9\)\pp{}. The exploratory v1 condition changed validation by \(+45.0\)\pp{} relative to C1, while verifier pass changed by \(0.0\)\pp{}. A four-cell development cross-tab likewise showed that several target behaviors occurred in both passing and failing runs. The task pool is synthetic and small; task-level minimum detectable differences were approximately 9.0--11.6\pp{} for the evaluated three-repeat models. These results describe this task pool and do not establish that written skills generally lack benefit.
\end{abstract}

\section{Introduction}
Natural-language procedures are a low-cost way to specify how a coding agent should inspect a repository, edit files, and validate its changes. A procedure can alter what an agent does without changing what a verifier accepts. Evaluations therefore need to measure both the final artifact and the trajectory that produced it.

This study asks whether a fixed written skill changes repository-repair success across models when the task specification, tools, verifier, and schedule are held constant. We constructed a small task pool with deterministic external checks, then compared a no-skill condition (C0) with a fixed baseline skill (C1). We also examined whether target behaviors separated passing from failing trajectories in development data and whether a revised skill could change those behaviors in a held-out subset.

The study makes three contributions:
\begin{enumerate}[leftmargin=1.4em,itemsep=1pt,topsep=2pt]
\item A task pool and harness with frozen external verifiers, admission checks, and complete tool-trajectory records.
\item A locked cross-model C0/C1 evaluation over 18 held-out tasks, with task-level paired analysis and a verifier-based primary outcome.
\item Descriptive evidence that process behavior can move without a corresponding change in verified outcome, including a four-cell behavior--outcome cross-tab.
\end{enumerate}

\section{Related Work}
Interactive language-model work has studied trajectories that alternate reasoning and actions. ReAct made such interleaving explicit and evaluated it across reasoning and interactive decision tasks \citep{yao2023react}. Our study takes the trajectory as an object of measurement, while asking a narrower question about fixed procedural instructions in repository repair.

Software-engineering agents are commonly evaluated through task completion against executable tests. SWE-bench uses real GitHub issues and repository-level changes with test-based evaluation \citep{jimenez2024swebench}; SWE-agent studies how an agent--computer interface changes software-engineering task performance and agent behavior \citep{yang2024sweagent}. Our task pool is synthetic and much smaller, but freezes each specification and verifier so the C0/C1 prompt contrast can be examined alongside detailed action traces.

Instruction-following evaluations have developed verifiable constraints for model outputs and agent settings. IFEval focuses on automatically checkable instructions \citep{zhou2023ifeval}; AgentIF evaluates longer, constraint-rich instructions in agentic applications, including tool-related constraints \citep{qi2025agentif}. These lines motivate separating instruction compliance from task success. A directly comparable, multi-model study of persistent repository-repair skills with held-out task-level inference remains to be established; this positioning is incomplete pending a targeted literature review \citep{TODO}.

\section{Methods}
\subsection{Task pool and study design}
\SkillTraj{} contains small repository-repair tasks with a task statement, a buggy seed, fixtures, and an external verifier. Development data were divided into diagnosis and validation subsets; the held-out set comprised 12 \texttt{test\_in} tasks from Skills A/B and six \texttt{test\_out} tasks from Skill C. Admission checks required positive fixtures to pass and buggy or shortcut fixtures to fail the verifier.

The primary comparison paired C0 (no skill) with C1 (the frozen v0 skill). Six model configurations were scheduled: \QwenWeak{}, \Gemma{}, \QwenStrong{}, \Coder{}, \Llama{}, and \GPT{}. The first five used runner r2; \GPT{} was executed through Codex and is reported as an uncontrolled reference anchor. \QwenWeak{} had five repetitions per task and all other C0/C1 configurations had three. Two qwen-only exploratory conditions were also run: a revised skill condition (v1) on the 12 \texttt{test\_in} tasks and a fixed call-32 reminder on all 18 tasks. The full schedule contained 870 runs.

The schedule and outcome protocol were specified in a hash-locked, timestamped plan before the held-out evaluation. The study was not externally preregistered. Conditions were interleaved using fixed per-model schedules. No task, verifier, fixture, or skill asset was changed during evaluation.

\subsection{Execution and outcomes}
Runner r2 recorded provider responses, parsed tool calls, command results, file edits, sampling metadata, terminal flags, and verifier outputs. It requested temperature 0.5, a seed when supported, up to 40 tool calls, a 65,536-token context budget, 120-second command timeouts, and a 1,200-second process-group timeout; metadata records requested and observed settings. Retry-exhausted provider errors were excluded from the primary pass-rate numerator and denominator. Hard timeouts and step-limit runs remained failures in the denominator. We report provider-error sensitivity with those runs counted as failures.

The primary outcome was the frozen Boolean \path{verifier.json.passed}, independent of the agent's final message. Terminal indicators such as \texttt{final\_empty}, \texttt{no\_edit}, and \texttt{timeout} were analyzed as non-exclusive process measures. A run with a final empty message could still pass the verifier.

\subsection{Statistical analysis}
The task was the sampling unit; repetitions estimated within-task variability. C0/C1 contrasts were task-paired and summarized by a fixed-seed, 10,000-draw paired bootstrap. Individual proportions use Wilson intervals. Wilson intervals describe single proportions and were not used as tests of between-condition differences. For process summaries, we report medians and interquartile ranges across task-level summaries, together with run-level occurrence rates where relevant.

Using observed within-task Bernoulli variance, approximate minimum detectable differences at two-sided \(\alpha=0.05\) and 80\% power ranged from 9.0 to 11.6\pp{} across the controlled three-repeat models. This is a design-level detectability bound, not an observed treatment effect.

\section{Results}
\subsection{Cross-model verifier pass}
All 870 scheduled run directories contained metadata and a Boolean verifier result. The controlled C0/C1 results were small and heterogeneous (\cref{tab:core}, \cref{fig:main}). \Gemma{} had a \(+5.6\)\pp{} task-paired difference, while \QwenWeak{}, \QwenStrong{}, and \Coder{} each differed by \(+1.9\)\pp{}. \Llama{} remained at a complete floor. The GPT reference anchor had identical marginal pass counts under C0 and C1, but its sampling was not controlled through r2. By split, \QwenWeak{} changed by \(+5.0\)\pp{} on \texttt{test\_in} and \(-4.2\)\pp{} on \texttt{test\_out}; \QwenStrong{} and \Coder{} changed direction across the two splits. One controlled task was all-zero and none was all-one across the model panel, limiting information from binary pass rates (\cref{tab:splits}).

\section{Discussion}
Across this task pool, changes in target behavior were more visible than changes in verifier pass. The revised skill shifted validation behavior substantially for the weak target in its exploratory subset, while the pass contrast remained centered at zero. The development cross-tab provides a complementary description: read-before-edit was universal in each cell, and validation, rereading, and rewrite avoidance did not uniquely mark passing runs. Together these observations caution against treating a checklist behavior as a proxy for task success.

The outcome-accounting audit also produced a methodological lesson. Earlier single-label summaries grouped some empty-final-message runs as failures even when the verifier passed. The primary analyses here therefore read success only from the verifier Boolean, while retaining terminal behaviors as separate, possibly overlapping indicators. Five retry-exhausted transport failures were excluded by the protocol; treating them as failures is the stated denominator sensitivity.

\subsection{Limitations}
The task pool is synthetic and self-authored, so it does not establish external validity for large real-world repositories. There are 18 held-out task units; repeated runs estimate within-task variability but do not increase the number of sampled tasks. The estimated minimum detectable differences of 9.0--11.6\pp{} indicate limited sensitivity to smaller changes. Floor and ceiling behavior further reduces information: \Llama{} was at a complete pass-rate floor, while one task was all-zero and no task was all-one across the controlled panel.

Repetition counts were unequal by design: \QwenWeak{} had five runs per task and other model configurations had three. \GPT{} was sampled through Codex, with a different tool surface and uncontrolled sampling, and is only a reference anchor. An initial batch of 104 \GPT{} usage-limit failures was overwritten after the owner requested a rerun; the overwritten archive was deleted, so potential selection differences between those attempts cannot be reconstructed. The current GPT cohort is not evidence about that discarded batch.

The development cross-tab is observational, and the v1 and call-32 reminder analyses are exploratory. Neither has a length-matched generic-prompt control. The reminder analysis also conditions on reaching its trigger point. Finally, human--judge comparison used one researcher annotator, incomplete blinding, and a small packet sample. The hash-locked, timestamped plan is not equivalent to independent preregistration. A larger task sample, matched prompt-length controls, and independently annotated trajectories would address these limits.

\section{Broader Impact and Ethics}
The task pool evaluates software-repair behavior in isolated workspaces and should not be interpreted as evidence of safe autonomous deployment. The paper reports model behavior and verifier outcomes, not judgments about individual users or developers. The human review component consisted of one researcher labeling anonymized trajectory packets; no external participant recruitment or personal data collection was performed.

\section{Outcome-Accounting Audit}
The legacy single-label outcome undercounted runs that passed the verifier but ended with an empty message. Reconstructing success from \path{verifier.json.passed} changed the earlier calibration queue from 102 to 110 passes among 175 usable runs, the original second queue from 8 to 18 among 28, the replacement-inclusive second queue from 12 to 24 among 36, and the development baseline/reminder queue from 25 to 48 among 72. These are outcome-accounting corrections, not performance changes.

\section{Human--Judge Agreement}
Across 24 blinded packets, macro Cohen's \(\kappa\) over five estimable labels was 0.588 (bootstrap 95\% interval 0.434--0.771); macro PABAK across all eight labels was 0.677 (0.552--0.781), and exact label-set agreement was 25.0\%. Interpretation is limited by the single researcher annotator, incomplete blinding, and small sample.
