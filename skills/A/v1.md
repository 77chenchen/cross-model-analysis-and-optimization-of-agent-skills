# Skill A — Code modification v1

Read `task.md` and the target implementation before editing. Convert every
constraint sentence in the task into a short private checklist, including
edge cases, input types, mutation requirements, return shape, and error
behavior.

Make the smallest complete change that satisfies the checklist. Prefer a
direct file edit over constructing complex source code through nested shell
quoting. After saving, re-read the edited target file to confirm that the
file contains the intended implementation.

Before reporting completion, run at least these two checks:

1. A syntax/import check appropriate to the language (for Python, use
   `python3 -m py_compile <target-file>`).
2. A small behavior check that exercises every material constraint in
   `task.md`, including malformed or boundary input where relevant.

If either check fails, repair the target and repeat both checks. Do not report
completion after an edit that was not re-read and validated. Do not alter
benchmark-owned tests or verifiers.
