# S7 qwen3.5:9b monitoring revision (2026-10-10)

## Scope and pre-registered interpretation

This is a monitoring and integrity-check snapshot of the completed qwen3.5:9b S7 runs only (330 runs). It is not the formal S7 analysis: the latter remains deferred until all 870 scheduled runs are complete. It changes no task, verifier, fixture, skill, prompt, parser, schedule, or runner setting.

The process hypothesis was written and committed before this revision and before producing any subsequent monitoring snapshot for another model: [`s7_process_hypothesis_preregistration_20261010.md`](s7_process_hypothesis_preregistration_20261010.md). It is: compared with C0, C1 has lower validation-after-last-edit frequency and more `write_file` rewrites and loops; v1 reverses those C1 directions. Qwen is the hypothesis-generating source. The other five models are independent checks, not evidence used to formulate the hypothesis.

## Addendum: validation definition sensitivity

The subsequently committed primary definition is **validation intent**: after
the final `write_file`, an executed `run_command` contains `test`, `pytest`,
`unittest`, or `py_compile`. The sensitivity definition is **transport success**:
after the final write, any `run_command` has `result.ok == true`. Both rates use
only runs that made at least one edit, so no-edit trajectories are not silently
called unvalidated. The read-only calculation is stored in
[`qwen_validation_definition_audit_20261010.json`](../data/s7_monitoring/qwen_validation_definition_audit_20261010.json).

| Definition | C0 | C1 | Task-level C1−C0 directions | C1−C0 Q1 / median / Q3 |
|---|---:|---:|---:|---:|
| Primary validation intent | 56/86 (65.1%) | 35/88 (39.8%) | 14 negative / 3 positive / 1 zero | −0.40 / −0.20 / −0.20 |
| Sensitivity transport success | 78/86 (90.7%) | 58/88 (65.9%) | 13 negative / 1 positive / 4 zero | −0.40 / −0.20 / −0.05 |

Both definitions therefore give the same descriptive direction—C1 has lower
post-edit validation than C0—across most tasks, though the absolute rate is
definition-dependent. This is a qwen monitoring observation, not a formal
condition comparison or a reason to change any locked S7 condition.

All values below are descriptive. The frozen activation parser remains unchanged (`skill-activation-heuristic-v1`). The structured machine-readable snapshot, including all quantiles, is [`qwen_monitoring_revision.json`](../data/s7_monitoring/qwen_monitoring_revision.json), generated by [`audit_s7_qwen_monitoring.py`](../harness/audit_s7_qwen_monitoring.py).

For each task, runs were averaged within condition before calculating a paired difference. The C1-minus-C0 differences over the 18 tasks are: validation mean −.267, median −.200 (14 negative / 2 positive / 2 zero tasks); rewrites mean +1.878, median −.200 (7 / 10 / 1); loops mean +1.200, median +.500 (10 / 6 / 2). Thus, the validation direction is widespread, whereas the rewrite mean is influenced by heterogeneous tasks and upper-tail values; it is not uniformly positive task-by-task. v1-minus-C1 on the 12 test-in tasks is validation mean +.467, median +.400 (11 / 0 / 1); rewrites mean −1.017, median 0 (5 / 4 / 3); loops mean −.617, median 0 (5 / 5 / 2). This is a monitoring check, not a condition comparison test.

The skill-family breakdown rules out a single-family explanation for the validation direction, while also showing why means alone would be misleading:

Each family shows a C1 validation decrease. Rewrite and loop means are much larger for B/C, while their medians are frequently zero; the full family-level median and quartile distributions are retained in the JSON record. Therefore these process differences cannot be described as a uniform, non-extreme effect.

## L3b pre-call-32 negative control

For this check, C1 and L3b traces were independently truncated to the first 32 tool calls. Only trajectories reaching call 32 enter the check: 12 C1 runs and 11 L3b runs, spanning five task pairs. Before call 32, every checked invariant matches: prompt hash by A/B/C skill family, v0 skill hash by family, tool schema version 2, and worker concurrency 1. Thus the L3b reminder itself has not yet been inserted in these prefixes.

The task-paired L3b-minus-C1 prefix differences are:

| Prefix metric | Mean | Median [Q1, Q3] | Task pairs |
|---|---:|---:|---:|
| First edit position | −.033 | 0 [−.333, 0] | 5 |
| Validation after last edit | −.133 | 0 [−.333, 0] | 5 |
| `write_file` rewrites | −1.767 | −3.667 [−7.500, 1.500] | 5 |
| Loops | −3.467 | −5.667 [−7.000, −5.167] | 5 |

They are not numerically identical despite having identical pre-trigger inputs. This is a negative-control diagnostic, not an L3b effect: selection on reaching call 32 produces a small, condition-specific subset, and the independent stochastic repeats are not seed-paired. The observed prefix disparity—especially loops—therefore records finite-sample and selection variation; it cannot be attributed to the reminder that occurs only after this prefix. It also means post-trigger process comparisons require the planned A/B layer handling rather than an unconditional C1--L3b interpretation.
